# ITCS386 Week 12 – UI Testing Lab

This is my individual Week 12 UI testing lab. I chose **Part 3 (Robot Framework)** and **Part 4 (Cypress)**. Both automate test case **QP-01**, which checks a custom pizza with restrictions, the login requirement for ratings, and the matching pizza in the admin list. I also tested Selenium's practice web form.

The automated tests were run on Windows 11 with Chrome 158. Their results and evidence are in `RESULTS.md`, `robot/results/`, and the Cypress screenshot/video folders. The manual QP-01 observations and intentional-failure exercises are documented separately where available.

## Project contents

- `robot/` — Robot Framework tests (`first.robot`, `web_form.robot`, `pizza_scenario.robot`), reusable locators/keywords in `resources/`, and two complete QP-01 runs in `results/run1/` and `results/run2/`.
- `cypress/` — JavaScript tests for the web form and QP-01, a custom admin login command, screenshots, and videos.
- `RESULTS.md` — environment versions, observed results, evidence, and Part B reflection.

## Requirements

- Google Chrome and a compatible ChromeDriver
- Python 3.10 or newer
- Node.js 22, 24, or 26

The tested setup used Chrome `158.0.8127.37`, ChromeDriver `158.0.8127.36`, Robot Framework `7.5.1`, Node.js `24.14.0`, and Cypress `16.3.0`. Cypress was updated to 16.3.0 after a compatibility issue with Chrome 158.

On Windows, keep ChromeDriver **outside the repository**. If it is under your home directory, configure the current PowerShell session with:

```powershell
$env:CHROMEDRIVER = "$HOME\drivers\chromedriver-win64\chromedriver.exe"
& $env:CHROMEDRIVER --version
```

## Part 0: Manual test

Run QP-01 by hand in Chrome while logged out: open [QuickPizza](https://quickpizza.grafana.com), turn on Advanced, set 600 maximum calories, exclude Knife, select vegetarian, and use a unique name like `Lab Pizza YYYYMMDD-HHMMSS`. Request the pizza, check the name/tool/calories, and click **Love it!** to check the login message. Then open `/admin` in the same browser, sign in with the site's practice credentials, and find the same pizza and tool. Record all seven actual steps and the locators in `RESULTS.md`; automated evidence is not a substitute for the manual run.

Do not use **Clear Ratings** on this shared practice site.

## Part 3: Robot Framework

Run these commands from the repository root:

```powershell
cd robot
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m robot first.robot
.\.venv\Scripts\python.exe -m robot web_form.robot
.\.venv\Scripts\python.exe -m robot -d results/run1 -v BROWSER:headlesschrome pizza_scenario.robot
.\.venv\Scripts\python.exe -m robot -d results/run2 -v BROWSER:headlesschrome pizza_scenario.robot
```

The two QP-01 runs produce `log.html`, `report.html`, `output.xml`, and screenshots in their respective `results/run*/` directories. Both submitted runs passed.

## Part 4: Cypress

From the repository root:

```powershell
cd cypress
npm.cmd install
npx.cmd cypress verify
npx.cmd cypress run --browser chrome
```

Run the final command a second time for a second full run. The tested setup uses Cypress **16.3.0**: if your local package is still 16.2.1, update it with `npm.cmd install --save-dev --save-exact cypress@16.3.0`. Screenshots are generated by `cy.screenshot()`; videos are enabled in `cypress.config.js`. Cypress normally replaces earlier run recordings, so the committed media shows the latest passing run. Both full Cypress runs passed (2/2 tests each).

To reproduce the wrong-title failure exercises, change `Web form` to `Web Form` temporarily in the relevant test, run it once, record the error in `RESULTS.md`, and restore the correct expectation. Do not commit the intentionally failing version.
